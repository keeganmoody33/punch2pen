Account

Sign-in is for the dictionary. It is not available in this build.

The account system that exists is email, then a six-digit code, to the Convex profile API. You do that in the plugin, so a portable dictionary can hang on a seat. This website is not that client. It will not take a code, and it does not open a portal.

Mail delivery on the current deployment is unset. Starting sign-in returns delivery_unconfigured: “Sign-in code delivery is not configured on this deployment.” Until a mail provider is configured, the API will not send a code, and the plugin has nothing to verify.

What sign-in is, when delivery exists

  1. The profile pill in the plugin opens the account. With no profile API in the build, the plugin already says sign-in is not available.
  2. You enter the email on the seat. The default signup mode is invite: if that email has no seat, the API answers not_invited. This page cannot create a seat.
  3. The API emails a six-digit code. The code is hashed, expires after ten minutes, and allows five attempts. This site does not enable the echo mail provider, which would return a code in the API response for development.
  4. You type the code in the plugin. A bearer session is stored on that Mac at ~/.punch2pen/account.json (mode 0600). There is no password in that file and no password on this page.

After that, Apply writes the correction pair onto the active seat’s dictionary. The playhead stays in the plugin, locked to the DAW clock. Workspace owners manage seats on the dashboard that ships with the API. That screen is not hosted here.

What you can do instead

The free utility does not need an account. Download it, punch in Logic, and correct words in the session. They will not survive an engine restart, and they will not leave the Mac.
